## 10. Context Window（上下文窗口）

### 1. 什么是 Context Window

我的理解：LLM 一次调用时，最多能够“看到并处理”的信息范围。
Context Window 是模型在一次请求中能够处理的最大上下文容量，通常使用 Token 数衡量，包括输入给模型的信息以及模型生成所需要占用的上下文空间。

TODO


### 2. Token 和 Context Window 有什么关系

我的理解：上下文窗口的大小是有限制的，例如128K Token，上下文中的内容是由token组成的，最多一次上下文窗口中只能包含128K个token。
Token 是模型处理文本的基本计量单位，Context Window 则表示一次模型调用最多可以容纳多少 Token。例如模型上下文窗口为 128K Token，那么本次请求中的 System Prompt、用户问题、历史消息、RAG 文档、Tool 结果以及模型输出等，都要受到这个容量限制。

最重要的是记：

Token = 单位
Context Window = 容量

类似：

MB = 单位
内存容量 = 多少 MB

### 3. LLM 为什么看起来能够记住之前的聊天？

我的理解：LLM 本身是不能记住之前的聊天的，但是可以通过上下文窗口来实现。
LLM 本身通常不会因为上一次调用而自动记住之前的聊天。聊天应用会保存历史消息，在下一次请求时，把相关历史消息重新放入 Context 中发送给 LLM，所以看起来像模型记住了之前的聊天。

重点差别就在：

不是：

LLM 自己记下来了

而是：

应用保存历史
↓
下一次重新提供给 LLM
↓
LLM 又“看见”了

这个区别以后学 Memory 时特别重要

### 4. LLM 本身是否拥有永久记忆？

我的理解：LLM本身不具备记忆能力
单次模型 API 调用本身通常是无状态的，模型不会天然拥有应用层意义上的永久记忆。长期记忆通常需要由应用借助数据库、Redis、向量库等外部存储实现。

为什么我不建议以后直接说：

“LLM 完全没有记忆能力。”

因为实际 AI 产品可能在模型之外增加 Memory 系统，用户感觉上确实会出现长期记忆。

所以以后要区分：

模型本身
≠
整个 AI 应用

这也是非常重要的工程思维。

### 5. 如果聊天记录越来越长，会出现什么问题？

我的理解：上下文超过上下文窗口的大小，会导致上下文截断，可能你最早问的内容它就不记得了。
聊天记录越来越长会消耗越来越多 Token。当内容接近或超过 Context Window 时，应用必须进行截断、摘要或筛选等处理，否则可能超过模型限制。被移出当前 Context 的历史内容，模型在这次调用中就无法直接看到。

这句话以后很实用：

“不在当前 Context 里的信息，模型这次就看不到。”

### 6. Context 和 Memory 有什么区别？

我的理解：Context
这一次调用
LLM 当前能够看到的信息
Memory
应用在模型调用之外
长期或阶段性保存的信息

需要的时候：

Memory
↓
取出相关信息
↓
放入 Context
↓
调用 LLM

Context 是 LLM 在当前一次调用中能够看到和处理的信息。Memory 则通常由应用系统负责保存，可以存储在内存、Redis、数据库或向量库等外部系统中。当模型需要这些历史信息时，应用从 Memory 中取出相关内容，再放入当前 Context 中发送给模型。因此 Memory 是存储机制，Context 是本次模型调用实际能够看到的信息。

### 2. Token 是什么？

TODO Token 是 LLM 处理文本时使用的基本单位。文本经过 Tokenizer 后会被拆成一个个 Token，模型实际上处理的是这些 Token。Context Window 的容量通常也使用 Token 数量来衡量。


### 3. Context Window 是什么？

TODO Context Window 表示一次模型调用能够处理的最大 Token 范围。不同模型的 Context Window 大小不同，例如某个模型可能支持 128K Token。


### 4. LLM 为什么会出现相同问题回答不完全一致？

TODO 因为 LLM 是概率生成模型，它会根据当前上下文和模型参数选择不同的 Token，因此同一个 Prompt 多次执行时，结果不一定完全一致


### 5. LLM 为什么可能产生错误答案？

TODO LLM 是概率生成模型，它不是从数据库中查询标准答案，而是根据当前 Context 和训练过程中学到的知识预测并生成后续 Token。因此它生成的内容可能看起来合理，但事实并不一定正确，这种现象通常称为“幻觉”。


### 6. LLM 本身为什么不能直接知道公司数据库的数据？

TODO LLM 默认无法直接访问公司数据库，数据库中的实时私有数据也不在当前 Context 中，因此模型不知道这些数据。需要由应用程序通过数据库查询、Tool 等方式取得数据后，再提供给模型。


### 7. 如果需要让 LLM 知道数据库中的信息，我认为应该怎么做？

TODO 如果需要让 LLM 知道数据库中的数据，应用程序需要先通过 Java Service、数据库查询或以后会学习的 Tool Calling 获取数据，然后把查询结果放入当前 Context，再让 LLM 基于这些真实数据进行分析和回答。


### 8. Context 和 Memory 的区别

TODO Context 是 LLM 在当前一次调用中能够看到和处理的信息。Memory 则通常由应用系统负责保存，可以存储在内存、Redis、数据库或向量库等外部系统中。当模型需要这些历史信息时，应用从 Memory 中取出相关内容，再放入当前 Context 中发送给模型。因此 Memory 是存储机制，Context 是本次模型调用实际能够看到的信息。


## 我认为今天最重要的三个知识点

1.LLM 是概率生成模型，不是数据库/搜索引擎。
2.Token 是 LLM 处理文本的基本单位；Context Window 决定一次能处理多少 Token
3.LLM 只能基于当前能看到的信息工作；外部数据必须由应用通过 Memory、RAG、Tool 等方式提供给它。
